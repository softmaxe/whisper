# Native migration acceptance map

[Specification #35](https://github.com/softmaxe/whisper/issues/35) defines the
behavior contract. The table covers all 65 user stories and points to existing
observable regression evidence. It is a transfer checklist, not proof that the
native app already implements the behavior. Native acceptance must drive the real
application workflow with controlled external boundaries, then verify the
physical and visual checks independently.

private helpers are prior art only; port their observable behavior, not their
implementation assertions. Run database cases against an actual isolated

## Reading the native evidence

The table below covers each of the 65 stories. `A` identifies automated workflow
or package evidence from actual test sources and reported results. It does not
substitute for final visual or physical acceptance. Follow
[the current checkpoint](native-migration-status.md) for later implementation,
package and CI results; do not add overlapping test counts from feature branches.

Remaining gates are `UI` for bilingual presentation and interaction, `HW` for
physical input/capture/focus/desktop effects, `PERF` for comparable packaged
samples and frozen budgets, `PKG` for the final package and CI, and `UPGRADE`
for actual signed installation and permission continuity. `IN PROGRESS` marks
source work still being completed. The earlier built-in microphone smoke is
limited to the observations in [its report](native-core-verification.md).
